# AI review log (raw notes for AI_USAGE.md)

Running list of places where the AI assistant (Claude Code) was wrong or subtly off, and how it was caught.
Chinmay: confirm each entry with your own review before it goes into AI_USAGE.md, and add your own.

| # | Milestone | What the AI did | How it was caught | Fix |
|---|---|---|---|---|
| 1 | M0 | Pinned `minio/minio` and `minio/mc` image tags from memory in docker-compose.yml. MinIO no longer publishes these images (Docker Hub repos return 404). | First `docker compose up` failed with "pull access denied". | Switched to RustFS (S3-compatible, Apache-2.0). Bucket is now created by our migrate step via the S3 SDK instead of a vendor CLI container, so any S3 store works. |
| 2 | M1 | Added a process-wide `verificationLinks` Map to production auth code so tests could read verification URLs. Test-only code in prod, and unbounded memory growth keyed by email. | Self-review of the diff before running tests. | Removed. Tests capture the logged link with `vi.spyOn(console, "log")`. |
| 3 | M1 | Initially planned to create the tenant account only in Better Auth's `user.create.after` hook. That hook runs after the user insert commits, not in the same transaction, so a failure would leave a user with no account. | Reading Better Auth's type docs for `databaseHooks`. | `ensureAccountForUser` is idempotent (advisory lock + membership check) and is also called on every dashboard load, so the state self-heals. |
| 4 | M0 | create-next-app 16 scaffold enabled `cacheComponents`; the AI almost kept the default. | Read the generated next.config.ts. | Disabled: every response here depends on the caller and live DB state. |
| 5 | M2 | First draft of the idempotency request hash covered method + path + body but not the key's mode, so a retry with identical body via a *test* key would replay a *live* job's response (and vice versa). | Self-review of `withIdempotency` against the test/live separation rule. | Mode is part of the hash; mismatch -> 422. |
| 6 | M2 | The scenario 12 test asserted 1,519 credits used; the correct number is 1,500 + 4×1 + 14 = 1,518. The *test* was wrong, not the code. | Test failed; recomputed by hand before touching code. | Fixed the expectation. Lesson: when a money test fails, prove which side is wrong first. |
| 7 | M2 | Ledger append-only test asserted on the top-level error message; Drizzle wraps Postgres errors, so the trigger's message is on `err.cause`. | Test failed with "Failed query: update…". | Assert on `cause.message`. |
| 8 | M3 | Added an optional `opts` parameter to `serializeGeneration`, which silently broke an existing `rows.map(serializeGeneration)` call: `map` passes the array index as the second argument. | `tsc` flagged the incompatible signature. | Explicit arrow `rows.map((r) => serializeGeneration(r))`. A reminder why point-free callbacks are risky. |
| 9 | M3 | Crash test: stopping the `npm run worker` task did not kill the `tsx`/`node` child on Windows; the "dead" worker kept processing jobs, which would have made the crash-recovery demo meaningless. | Probe job still got processed after the "kill"; listed node processes. | Kill the node processes directly for the test. Host-only issue: in Docker, stopping or killing the container takes down its whole process tree. For the demo, kill the worker container (`docker compose kill worker`). |
| 10 | M4 | First version of `POST /v1/webhook_endpoints` ran through the generic idempotency layer, which stores the response body for replays — that would have written every endpoint's signing secret to `idempotency_keys` in plaintext for 24h (and returned it again on replay). It also created the endpoint in a separate transaction from the idempotency record. | Self-review: "where does this response body go?" | `ApiResult.replayBody` lets a route store a redacted body (`secret: null`); endpoint creation now runs in the idempotency transaction. Test scans every table for the secret. |
| 11 | M4 | Passed `maxRedirections: 0` to undici; in undici 8 redirects aren't followed by `request()` at all and the option is only accepted as 0. | Read undici's source (`lib/core/request.js`). | Removed the option; a test asserts a 302 to 169.254.169.254 is not followed. |
